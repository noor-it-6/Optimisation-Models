Problem type: employee scheduling models

An employee scheduling model decides how many people to put on each allowed shift pattern so that every period has enough staff, at the lowest cost or with the fewest people. It is also called a covering model: each pattern covers several periods, and together the patterns must cover every period's requirement.

How to recognise one

  • Time is split into periods (days, hours, shifts), each with a minimum number of staff.
  • People work fixed patterns that span several periods, set by contracts or union rules.
  • The decision is how many people start each pattern, not how many work each period.
  • Each constraint says the staff on duty in a period, added over every pattern that covers it, is at least the requirement.

The key modelling idea

"Number working on Monday" looks like the obvious variable, but it cannot respect the five-days-on rule. Choosing who starts on which day builds the rule into the variables, and the days each person works follow automatically.

Pattern matrix

Every scheduling model has a 0/1 matrix saying which periods each pattern covers. Change the matrix and the same model handles 4-day weeks, split shifts or 8-hour shifts within a day.

Check yourself: is it a scheduling model?

A ward needs a minimum number of nurses in each 4-hour block of the day; nurses work 8-hour shifts starting at any block.

Yes. Periods are 4-hour blocks, patterns are 8-hour shifts (each covers two blocks), and the variables are how many nurses start in each block.

SureStep hires and fires workers each month so production meets shoe demand at least cost.

No. It decides workforce size and production over time, not which shift patterns people work. That is an aggregate planning model.

A bank decides how many clerks start each weekday shift so cheques are encoded on time each day.

Yes. This was one of the original applications of employee scheduling models.

02

Seven possible shift patterns

An employee's start day fixes the five days they work. Each row is a pattern; a filled cell means "works that day". Select a day to see which patterns cover it.

Columns become constraints

Read the matrix down a column to build that day's constraint. Monday is covered by employees starting Monday, Thursday, Friday, Saturday or Sunday: \(X_1 + X_4 + X_5 + X_6 + X_7 \ge 17\).

Rows wrap round the week

A Thursday starter works Thursday to Monday. The week is treated as a repeating cycle, which is why this is called a static (cyclic) model.

Table 1. Model notation table.
NotationDescription
Sets\(I\)Set of days of the week, \(I = \{1,\dots,7\}\) (Monday to Sunday), indexed by \(i\) for the start day and \(j\) for a day worked
Parameters\(R_j\)Number of employees required on day \(j \in I\)

Decision variables\(X_i\)Number of employees starting their five-day shift on day \(i \in I\)
Variables7one per start day
Constraints7one per day covered
Model typeIPinteger program

The objective (1) minimises the total number of full-time employees. Constraints (2) ensure that for each day, the number of employees working that day, counted over every start day whose pattern covers it, is at least the number required. Constraints (3) ensure that the number starting on each day is non-negative, and constraints (4) ensure that it is a whole number. Without (4) the model is a linear program whose answer can include fractions of employees.

Where is \(A_{ij}\) in Excel?

There is no 0/1 table in the workbook. The blank cells in the grid play the role of \(A_{ij} = 0\), and each reference such as =$B$4 is \(A_{ij} = 1\) times \(X_i\). Summing a column then gives \(\sum_i A_{ij} X_i\).

Integer constraints and Solver options

If Solver's "Ignore integer constraints" option is ticked, or the integer optimality tolerance is loose, Solver returns the LP answer of 22.33 even with the integer constraint in place.

Why not just round the LP answer up?

Rounding each fractional start-day up gives 2 + 4 + 2 + 8 + 0 + 4 + 5 = 25 employees, two more than needed. Rounding down can break a coverage constraint. Solving with integer constraints finds 23.

No. The LP, which is allowed fractions, cannot do better than 22.33. Any whole-number schedule is also allowed in the LP, so no whole-number schedule can beat 22.33, and the best is 23.

Why does each extra employee per day cost more than one extra employee?

Adding one to every day adds 7 person-days, and each employee covers only 5. So the total rises by about 7 ÷ 5 = 1.4 employees each step: sometimes 1, sometimes 2 in the integer model.
